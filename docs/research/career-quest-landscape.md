# Career Quest: исследование и решение для хакатона

Дата проверки источников: 23 сентября 2026.
Условия: 4 часа, один участник, небольшой опыт программирования, разработка с Codex, OpenAI API и заявленные NVIDIA-кредиты $50.
Уточнение пользователя: аудиозаписи относятся к другому кейсу и не входят в Career Quest.

## 1. Вывод

Рекомендую «Следующий полезный шаг»: сотрудник видит препятствия к следующему грейду, получает 1–3 существующие активности с объяснением, сравнивает результат выбора и отмечает выполнение. Прогресс рассчитывается по данным, а агент помогает выбрать среди допустимых вариантов.

Это специализированный прототип под правила Halyk. Нельзя заявлять мировую новизну карьерного AI-агента: Gloat, Fuel50 и Eightfold уже предлагают похожие возможности. Конкурсное преимущество нужно показывать через корректность на новых профилях, понятные причины выбора, обработку отказов/пропусков и воспроизводимость.

Исследование основано на ТЗ и публичных страницах производителей. Продукты конкурентов не тестировались, аккаунты OpenAI/NVIDIA не проверялись, платные API-вызовы не выполнялись. Отсутствие функции на странице не доказывает её отсутствие в продукте.

## 2. Что требует ТЗ

Источник: пользовательский PDF «HackAlem AI_ Career Quest - платформа геймификации жизненного цикла сотрудника..pdf», страницы 2–5.

- Профиль, история, навыки, требования следующего грейда.
- 1–3 рекомендации и объяснение минимум по трём факторам.
- Обновление навыков после завершения по gain/max_level из events.json.
- HR: частые дефициты навыков, участие и сотрудники без рекомендованного шага.
- Загрузка дополнительных профилей и истории в исходном формате: жюри проверяет три новых профиля.
- Интерфейс до 2 секунд, рекомендация до 10 секунд.
- Сотрудник и HR имеют разные права; чужая история вовлечённости не раскрывается сотрудникам.
- Репозиторий, README, запуск одной командой.
- Данные: 200 сотрудников, 40 событий, 60 навыков, 24 месяца истории; kit содержит JSON/CSV и README. Наличие готового кода приложения не обещано.
- Данные синтетические; их нельзя распространять за пределами хакатона. Для публичных примеров использовать собственные допустимые фикстуры.

Геймификация опциональна. Публичные рейтинги сотрудников и очки за обязательные процессы запрещены. Данных о KPI, производительности труда и загрузке в описании набора нет. Не придумывать эти поля и не делать их обязательными для рекомендаций.

Баллы: работоспособность 25, техническая реализация 25, README/воспроизводимость 25, ценность 15, оригинальность 10. Поэтому полный основной сценарий важнее дополнительных игровых экранов.

### Что им «не хватает»: граница доказательств

Документально подтверждённую критику нельзя подменять предположениями. Мы не установили, что у конкурентов отсутствуют объяснения, учёт истории, агенты, русский/казахский или прогноз эффекта.

Наши проверяемые возможности для кейса:
1. Объяснить, почему событие A полезнее B именно по выданным данным.
2. Рассчитать точный прирост по gain/max_level и показать оставшийся разрыв.
3. Перестроить рекомендацию после завершения и на новом профиле без правок кода.
4. Честно показать «нет подходящей активности», вместо выдумывания события.
5. Свести действия сотрудника к выбору следующего шага и подтверждению выполнения.

Первые четыре можно доказать на защите. Пользу последнего нужно проверить коротким прохождением сценария реальным человеком; нельзя заранее обещать рост вовлечённости.

## 4. Варианты продукта

Все варианты обязаны сохранять профиль, рекомендации, прогресс, HR и импорт.

### A. Следующий полезный шаг — рекомендовано

Первый экран: цель по грейду, критичный разрыв, 1–3 карточки действий.
В карточке: почему сейчас, факты из профиля/истории, ожидаемое изменение навыков, альтернативный вариант.
Преимущество для защиты: легко сравнить с простым правилом «выбери минимальный навык».
Риск: агент может только пересказывать жёстко заданный ответ. Дать ему сравнивать несколько корректных кандидатов через инструменты.
Объём: лучший шанс уложить обязательный минимум в четыре часа; оценка условна до чтения kit и проверки API.

### B. Маршрут из нескольких шагов

Сотрудник сравнивает две последовательности из 2–3 мероприятий и видит оставшиеся пробелы.
Преимущество: наглядная история развития и симуляция.
Риск: порядок, повторы и взаимодействие gain/max_level усложняют расчёт.
Решение: сначала реализовать A; маршрут — только после полного основного сценария. Не обещать автоматическое повышение.

### C. Развитие в ходе реальной работы

Рекомендовать проект, менторство или практическую активность, если соответствующие события есть в каталоге.
Преимущество: близко к желанию пользователя развиваться без лишнего администрирования.
Риск: ТЗ не предоставляет KPI, Jira, календарь и загрузку; нельзя достоверно оценить влияние на бизнес-результат.
Решение: использовать имеющиеся типы событий. Интеграции и связь с KPI вынести в дальнейшее развитие.

### D. Подбор с короткой обратной связью

Сотрудник отклоняет рекомендацию с причиной, агент предлагает другой допустимый вариант.
Преимущество: добровольность и менее раздражающий интерфейс.
Риск: причина пропусков неизвестна; нельзя выводить из них лень или низкую мотивацию.
Решение: дополнительное действие после A; до уточнения трактовать историю как ограниченный сигнал. Не исключать критичный навык навсегда.

Выбор: A с компактным сравнением альтернатив. Добавить D, только если остаётся время.

## 5. Как использовать OpenAI и NVIDIA

### OpenAI — агент основного сценария

Кандидат: gpt-5.6-terra. Официально поддерживает function calling и Structured Outputs. Начать с небольшого reasoning effort, проверить реальную задержку на нескольких профилях; доступ конкретного аккаунта не установлен.

- Агент получает только контекст одного сотрудника, требования грейда и кандидатов.
- Инструменты возвращают идентификаторы событий, вычисленные изменения и факты истории.
- Финал — валидируемый JSON с event_id, причинами и ссылками на факты.
- Числа, существование событий и права доступа проверяет код.
- Structured Outputs обеспечивает структуру, но не гарантирует истинность содержимого.

Источники: [модель](https://developers.openai.com/api/docs/models/gpt-5.6-terra), [function calling](https://developers.openai.com/api/docs/guides/function-calling), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

### NVIDIA — сравнение во время разработки или альтернативный основной провайдер

В каталоге проверен hosted-пример nvidia/nemotron-3.5-lightning-30b-a3b через OpenAI SDK с base_url https://integrate.api.nvidia.com/v1. Это кандидат для короткой проверки, а не подтверждение работоспособности пользовательского ключа.

Полезное применение кредитов:
- прогнать те же сложные профили и сравнить выбор с OpenAI;
- попросить найти фактические противоречия в объяснении; затем сверить замечания кодом/человеком;
- создать дополнительные синтетические профили, сохраняя схему, и вручную определить приемлемые ответы.

Мнение второй модели не является правильным ответом по определению. Основной критерий — данные и правила задания. В демонстрационном запросе оставить один провайдер: вызов двух моделей подряд увеличивает задержку.

Hosted API и self-hosted NIM — разные способы запуска. API-кредиты не означают наличие собственного GPU-сервера. Тариф, срок действия и применимость заявленных $50 неизвестны без условий выдачи кредита.

Источники: [hosted model card и пример](https://build.nvidia.com/nvidia/nemotron-3.5-lightning-30b-a3b), [NVIDIA API catalog](https://docs.api.nvidia.com/nim/re/reference/llm-apis), [NIM tool calling: зависит от модели и развёртывания](https://docs.nvidia.com/nim/large-language-models/1.15.0/function-calling.html).

### Стоимость: иллюстрация, не измерение

На странице gpt-5.6-terra указаны $2 / 1M входных и $12 / 1M выходных токенов для обычных коротких запросов. Если один полный цикл всех вызовов потребует суммарно 6000 входных и 800 оплачиваемых выходных токенов, стоимость составит $0.0216, а 100 таких циклов — $2.16. Реальные расходы зависят от повторных запросов, reasoning-токенов и длины контекста. Для NVIDIA аналогичную сумму без тарифа не вычисляем.

## 6. Реальная agentic-логика

Предлагаемый простой цикл:
1. Приложение определяет пользователя и собирает компактные факты профиля.
2. Агент запрашивает список допустимых событий.
3. Выбирает несколько событий для сравнения и вызывает simulate_events сразу для группы.
4. Получает рассчитанные результаты и формирует рекомендацию.
5. Код валидирует событие, факты и уровни, интерфейс показывает результат.
6. Пользователь отмечает выполнение; сервер один раз обновляет историю/навыки; следующий запрос использует новое состояние.

Ограничить цикл тремя обращениями к модели и общим лимитом 10 секунд, ориентируясь на ТЗ. Это проектный предел; выполнение за 10 секунд необходимо измерить. При таймауте показать прозрачный базовый результат по правилам с пометкой, что AI-рекомендация не получена. Это восстановление интерфейса, а не выполненное AI-требование.

Показывать названия вызовов, их результаты и краткие причины. Не показывать скрытые рассуждения модели и не рисовать фиктивную активность инструментов.

## 7. Стек и модули

При отсутствии готового приложения рекомендую Python + Streamlit + SQLite + OpenAI SDK + Pydantic. Один процесс уменьшает время на связку frontend/backend. GPU, vector DB, fine-tuning и сложный framework агентов для 40 событий не нужны.

| Модуль | Ответственность | Условие готовности |
|---|---|---|
| data.py | JSON/CSV, валидация, импорт новых профилей | Новый профиль проходит тот же путь, что исходный |
| career.py | Требования грейда, допустимость событий, расчёт прироста | Цифры совпадают с ручным расчётом и README kit |
| agent.py | Провайдер, инструменты, ограниченный цикл, проверка ответа | Реальный tool call и валидная рекомендация |
| store.py | Состояние выполнения, история, ограничения ролей | Повторный клик не начисляет прогресс повторно |
| app.py | Профиль, карточки, сравнение, HR, импорт | Сквозной путь доступен без редактирования кода |
| README / demo notes | Установка, запуск, данные, ограничения, демонстрация | Другой человек запускает по инструкции |

Простой демонстрационный вход с заранее заданными ролями допустим как прототип, но сервер должен проверять доступ: сотрудник видит свой профиль, HR — разрешённый срез. Переключатель внешнего вида сам по себе не является разграничением прав.

| 20–60 | Загрузка профиля, разрывы, симуляция gain/max_level, импорт | Числа проверены на одном примере и новом профиле |

| 105–145 | Карточки, объяснения, подтверждение выполнения, сохранение | Действие меняет прогресс и следующий совет |

План напряжённый, не гарантия сроков. При отставании сначала убрать сравнение провайдеров, отклонение с причинами и визуальную полировку. Сохранить обязательные рекомендации, импорт, прогресс и HR.

Параллельно безопасно: пока Codex делает доменную логику, пользователь читает kit, формулирует ожидаемые ответы и готовит историю демонстрации. Если позже поручать UI другому агенту, сначала зафиксировать общий JSON-формат; не давать двум агентам одновременно менять app.py, зависимости и базу данных.

## 9. Что проверять

Это будущий план проверки; результаты ещё не получены.

| Случай | Ожидание |
|---|---|
| Самый слабый навык не является приоритетом следующего грейда | Выбор учитывает грейд, пользу и историю |
| Повторные пропуски активностей одного типа | История объясняет компромисс; причина пропусков не выдумывается |
| Навык уже достиг max_level события | Нулевой прирост не выдаётся за развитие |
| Событие уже выполнено | Повтор учитывается согласно kit; двойное начисление от повторного клика исключено |
| Нет допустимой активности | Честный статус и причина, без выдуманных событий |
| Новый профиль/история | Импорт без изменения кода |
| Нет истории или требований следующего грейда | Явно отмечены недостающие данные |
| Описание события содержит «игнорируй правила» | Текст остаётся данными, права и инструменты не расширяются |
| Таймаут API | Ограниченное завершение, прозрачный fallback |
| Русский/казахский вывод | Идентификаторы и числа сохраняются, язык отдельно проверяется |

Заранее отметить допустимые рекомендации для 8–10 маленьких профилей. Сравнить простое правило, многофакторный baseline и агент. Показать: число валидных событий, обоснования с тремя подтверждаемыми факторами, совпадение с допустимыми ответами, задержку и корректность прогресса. Такая мини-проверка не доказывает рост вовлечённости или универсальное качество.
